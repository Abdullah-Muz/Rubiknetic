# Review 3 of the play-criteria proposal (revision 3)

Reviewer: independent adversarial reviewer (third review). Scope: criteria text in `review3_proposal.md`, checked against
`src/rubiknetic/cube_physics/scored.py` (the file is here, not under `experiments/`), `src/rubiknetic/cube_physics/readout.py`,
`src/rubiknetic/cube_physics/rig.py`, `experiments/D8_alignment/d8_1b_stage1.py`, and `experiments/PHASE_1_PREREGISTRATION.md`.
No result folders, summaries or decision log were read. No simulations were run; arithmetic only.

## Verdict: ACCEPTABLE WITH CHANGES

The move criteria (D-T, D-A, D-L, D-S) are sound in one dimension and correctly implement review 2's changes, except that
the frame of the lattice reference is mis-stated. The rest criteria do not carry the "toward square only" principle into
three dimensions, and R-L has an undefined reference. Under both defects, behaviour that M1 rejects would pass. Five changes are required.

---

## 1. Facts established from code and pre-registration

- FACT (`scored.py:252, 258, 261, 264`): drift is `|rotation_about_deg(r0, r1, nontarget, face)|`, with `r0` sampled before
  `tr.rig.turn` and `r1` after it returns. FACT (`rig.py:164-182`): `turn` issues the close command first, then closes (0.3 s),
  turns, holds, opens (0.3 s) and settles (0.3 s). So `r0` is "before the close command" and `r1` is "after open + settle".
- FACT (`readout.py:30-36`): `poses()` returns rotations **in the core frame** (`rc.T @ R_body`), not the MuJoCo world frame.
- FACT (`readout.py:48-59`): `rotation_about_deg` is the in-plane angle of a projected tangent vector, computed by `arctan2`.
  It is therefore wrapped to (−180°, 180°], not "unwrapped". This is harmless below 180°.
- FACT (`d8_1b_stage1.py:100-105`): the lattice error is `rotvec(rot[i] @ nearest_lattice_rotation(rot[i]).T)`, with `rot`
  taken from `ro.poses(d)`, so in the **core frame**.
- FACT (`scored.py:323-332`): M1 rest uses `r0` after the setup settle and samples every 50 steps. It takes the twist about each
  face normal for the members of the 6 face layers, so a corner is measured about all 3 axes and an edge about 2.
- FACT (pre-registration line 49): every layer starts with a uniform ±1° misalignment, applied before t = 0. INFERENCE: on a
  play cube, |a₀| and e₀ will therefore often be at or above the caps (0.5° and 0.25°), so the allowance will usually be fully granted.
  The counterexamples below are therefore the typical case, not edge cases.

## 3. Required changes

### R1. Specify the core (cube) frame for a₀, a₁, eₜ and Δ. "World-frame" is wrong and gameable.
- Quote: "a₀,ᵢ is piece i's signed twist about the same axis of its **world-frame** lattice error (`R·Lᵀ`, `d8_1b_stage1.py:105`)".
- FACT: the cited line uses core-frame rotations, and Δ (`rotation_about_deg` on `poses()`) is core-frame. The text and the code disagree.
- INFERENCE: today the core may sit at the world lattice, but the project's target rig is an xArm7 holding the cube. Then the
  core's attitude in the world is arbitrary, and a world-frame "square" is not the cube's square.
- **Counterexample (moves):** the cube is held at +3° yaw in world. A non-target piece is exactly square relative to the core,
  and the move drags it −1.5° (a true drag *away* from square).
  - World-frame a₀ = +3.0 and a₁ = +1.5, same sign, so away-motion = max(0, 1.5 − 3.0) = **0**: D-A passes.
  - D-T: 1.5 ≤ 1 + min(3, 0.5) = 1.5: passes.
  - D-L passes if only one piece moves; D-S gives 1.5·7/8 = 1.31 ≤ 1.5 in the 8-piece layer: passes.
  - M1: 1.5 > 1: **fails**.
- The same mismatch corrupts eₜ in R-A.
- **Fix:** "All lattice errors and relative rotations are computed in the core frame returned by `Readout.poses()`, with the
  error as R·Lᵀ in that frame. a₀ and Δ must use the same frame and the same axis sign as `rotation_about_deg`."

### R2. The rest allowance must be credited only to motion *toward* square. In 3-D it currently is not.
- Quotes: R-T "≤ 0.5° + min(|e₀,ᵢ|, 0.25°), where e₀ is the norm of its lattice error". R-A "max(0, |eₜ| − |e₀|)".
- FACT: R-T grants the full credit whenever e₀ ≠ 0, whatever the direction of motion. R-A compares *norms*, and a norm grows only
  quadratically for motion orthogonal to e₀. The principle in §2 ("motion away from square … limited exactly as in M1") is
  therefore not implemented at rest. In moves the problem does not arise, because a₀ and Δ are both scalars about one axis.
- **Counterexample A (sag about another axis):** a corner with e₀ = 0.25° about x (left from the ±1° setup misalignment) sags or is
  pulled by a magnet pair 0.70° about y during the first 5 s and stays there.
  - R-T: 0.70 ≤ 0.75: passes.
  - R-A: √(0.25² + 0.70²) − 0.25 = 0.493 ≤ 0.5: passes.
  - R-L: about 0.70/8 ≈ 0.09 for that piece's y-layer: passes.
  - R-S: 0 if the piece is still in the last 5 s: passes.
  - M1: the corner belongs to an L/R face, so its twist about y is 0.70 > 0.5: **fails**.
  - Limit: orthogonal motion up to √(0.75² − 0.25²) = 0.707° passes, 41% above M1.
- **Counterexample B (pure away-motion on a square axis):** the same corner settles 0.25° to square about x and drifts 0.70° away
  about y. It ends at (0, 0.70), 0.70° off square on an axis where it began square.
  - R-T: √(0.25² + 0.70²) = 0.743 ≤ 0.75: passes.
  - R-A: 0.70 − 0.25 = 0.45: passes.
  - M1: 0.70 > 0.5: **fails**.
- **Fix:** write rₜ for the rotation vector of Rₜ·R₀ᵀ (core frame) and ê₀ = e₀/‖e₀‖. Let the credit be
  c = clip(−rₜ·ê₀, 0, min(‖e₀‖, 0.25°)). Require **‖rₜ + c·ê₀‖ ≤ 0.5°**, which is the motion left after removing the credited
  toward-square component. This is the exact 3-D analogue of D-T with D-A. Also add counterexamples A and B as fault tests.

### R3. Define R-L's reference: rotation since t = 0, not lattice twist.
- Quote: R-L "max over the 10 s of |mean **twist** of its non-centre pieces about the layer axis|".
- FACT: §3.1 uses "twist" both for Δ (relative motion) and for a₀ ("signed twist … of its lattice error"), so either reading is available.
- **Counterexample:** a whole layer slips coherently at rest from a lattice twist of −0.30° to +0.45° (0.75° of motion).
  - With the lattice reading, R-L = max(0.30, 0.45) = 0.45: passes.
  - R-T: 0.75 ≤ 0.5 + 0.25: passes. R-A: 0.45 − 0.30 = 0.15: passes. R-S: passes if the slip happens in the first 5 s.
  - M1: 0.75 > 0.5: **fails**.
  - With the relative reading, R-L = 0.75: fails, as it should.
- **Fix:** "mean over the layer's non-centre pieces (membership at t = 0) of `rotation_about_deg(r_0, r_t, members, axis)`".
  Add this fault test.

### R4. Give "M4-derived" an operative consequence.
- Quotes: "It never applies to M4". §4.2 "Near-copies of M4 (B1 + magnets at another gap) count as M4-derived."
- FACT: no rule says what follows from being M4-derived. INFERENCE: these criteria were designed after inspecting M4's data. A
  near-copy (same family, a different gap) is exactly the case where criteria tuned post hoc are most likely to fit, and it could
  enter through "a new pre-registration for a future mechanism".
- **Fix:** state one of the following explicitly:
  - (a) revision 3 never applies to M4-derived mechanisms; or
  - (b) it may apply only with the post-hoc and M4-derived status printed in the verdict line, and with G1 sign-off required even if
    M1 passes.
  The choice is the user's. Leaving it undefined is the gap.

### R5. Specify the marginal negative control so that its outcome cannot be chosen.
- Quote: "a scripted marginal drag of 1.2–2° (a logged test wrench on one non-target piece during a move) must fail".
- FACT: by design, a 1.2–1.5° drag *toward* square on a piece with |a₀| ≥ 0.2–0.5° passes D-T and D-A. So the control's result
  depends on unstated choices (direction, the piece's a₀, magnitude). INFERENCE: an implementer can choose a 2° away-drag that
  fails trivially and demonstrates no sensitivity at the margin.
- **Counterexample:** a₀ = +0.4°, drag −1.3°. D-T: 1.3 ≤ 1.4 passes. D-A: crossing gives |a₁| = 0.9 ≤ 1 passes. The "must fail" control
  fails to fail, and the protocol does not say what happens next (a forking path).
- **Fix:** pre-specify at least three control cases and their expected outcomes:
  - (i) away from square from |a₀| ≤ 0.1°, by 1.2°: must fail D-A and D-T;
  - (ii) toward and across square from a₀ = 0.5°, by 1.6°: must fail D-T;
  - (iii) a rest-phase test wrench producing counterexample B: must fail (after R2).
  Pick the piece by a rule (e.g. the first non-target corner in HOME order), not by choice.

## 4. Optional changes

- **O1. Pre snapshot.** "immediately before the pads close" can be read as "before contact", which is up to 0.3 s later. Define it
  as "before the close command, at the code position of `scored.py:252`". For a future gripper rig, define the equivalent event.
- **O2. Isolate each criterion in its fault test.** Several faults start from square, so D-T fires as well, and the named criterion
  is never shown to be the only barrier. Examples:
  - "Coherent slice rotation 1.1°" also fails D-T, because 1.1 > 1 from square. Isolate it as: slice at a₀ = +0.5, dragged −1.1.
  - D-S is never the sole failing criterion. Isolate it as: one piece a₀ = −0.5 → +1.0 (Δ = +1.5), seven pieces Δ = −0.5. Then the
    mean is −0.25 and the deviation 1.75; D-T, D-A and D-L pass.
  - The R-S oscillation fault needs a stated frequency.
- **O3. R-S sampling.**
  - "every 10 physics steps (5 ms at the 0.5 ms timestep)" is fixed in steps, not in time. Path length of jitter scales with the
    number of samples, so fix it in time (5 ms).
  - Vibration at 200 Hz (period equal to the sampling interval) is invisible. M1 is equally blind, so this is not a regression; a
    200 Hz fault test would document it.
  - Report the R-S noise floor on the positive control. R-S is *stricter* than M1 and may reject on solver jitter.
- **O4. Applicability test.**
  - State which corner and edge are tested (all, or chosen by a rule), whether the torque acts about the cube axis or the piece
    centroid, and whether the reading is the peak during the hold or its end value.
  - INFERENCE: the gate does not bound the allowance (that comes from a₀), so ambiguity here is low-risk. Still, "one corner and one
    edge" lets the implementer pick the tightest piece against the 1.5° upper limit.
- **O5. Definitions.**
  - Define rest t = 0 as "after the setup settle, at `scored.py:323`".
  - Replace "unwrapped" with "relative rotation, wrapped to ±180°, single-valued for |Δ| < 180°".
- **O6. Justify D-S by M1's implied bound.** M1's |Δ| ≤ 1° implies a maximum deviation from the layer mean of 1.5° for a 4-edge
  slice and 1.75° for an 8-piece layer. So D-S = 1.5° is no looser than M1, and that is a better justification than "equal to D-T's
  maximum".

## 5. Are the numbers principled? Are the safeguards enough?

- **The allowance (half the threshold).** It is arbitrary but simple, the same for moves and rest, disclosed, and capped
  independently of any declared parameter. That is acceptable for a pre-registration made before the new mechanism's data.
  INFERENCE: with the disclosure section removed I cannot judge whether 1.5° was set just above observed tails. That is why R4 matters.
- **D-S at 1.5°.** Principled via M1's implied shear bound (O6).
- **R-S (0.5° over 5 s).** A new, stricter quantity with no M1 counterpart. It does not loosen anything.
- **Applicability numbers.** The 0.5° entry line reuses M1's limit, and 0.02 N·m reuses D1's torque: reasonable. The 1.5° upper
  limit is tied to D-T.
- **Safeguards.** Equal-prominence M1 reporting, G1 sign-off for any rev3-pass/M1-fail case, and "never M4" are good. They fall
  short because of R4 and R5, and because the fault list has no rest test with motion orthogonal to e₀.

## 6. Counterexamples tried that do NOT break revision 3 (for the record)

- **Coherent non-target layer drag through square** (a₀ = +1.0, Δ = −1.5 for all 8 pieces): caught by D-L (1.5 > 1).
- **Half-layer drag** (a₀ = +1.0, Δ = −1.5 on 4 of 8 pieces): passes revision 3 and fails M1. Each piece only uses its own
  0.5° toward-square credit, and each ends nearer to square (−0.5). The internal relative motion (1.5°) is within M1's implied 2°.
  This is the approved principle, not a defect.
- **Alternating crossing in the slice** (a₀ = ±0.5, Δ = ∓1.5): passes at the D-S boundary. Each piece is within its own allowance.
  Principle-consistent.
- **90° accidental non-target turn:** Δ ≈ 90, D-T fails. No wrap, because a₁ is propagated.
- **Accumulating misalignment** of 1° per move: M1 permits it equally. It is caught only by the unchanged E1-4 growth slope.
- **Transient drag that recovers before post:** invisible to both M1 and revision 3, because both use only the pre and post
  snapshots. No regression.
