# Rubiknetic — Reinforcement Learning Experiment Specification

**Status:** Approved architecture; proposed implementation details subject to Phase 3 pilot.  
**Control selection:** E (hierarchical/residual) + C (Cartesian action) + D (force/impedance-aware), one learned turning arm initially.

## 1. Research question and falsifiable hypothesis

Can bounded residual RL applied to a classical Cartesian/impedance face-turn controller improve **physically verified face-turn success, contact robustness, or execution cost** under held-out poses, friction variation and disturbances, relative to the *same controller without residuals*?

Null result is acceptable. The objective is not to manufacture a policy-improvement result.

## 2. Prerequisites

- Phase 1 legal physically driven cube turns, independent puzzle-state oracle, no teleportation.
- Phase 2 xArm7 + candidate gripper mounting, valid contact geometry, conventional stabilizer and repeatable classical turning baseline.
- Baseline logs including torque, contact, slip, target and adjacent-layer state, and CPU steps/sec.
- Controlled training reset states explicitly differentiated from evaluated full-episode states.

## 3. Initial single-skill MDP

| Element | Initial proposed design |
| --- | --- |
| Task | Arm B performs one commanded 90° rotation of a selected face; Arm A classically stabilizes cube |
| Observation | Relative end-effector/target-face pose, current face angle estimate, target angle/error, arm joint state, gripper aperture, contact wrench estimate, nominal motion error, relevant mode, elapsed fraction |
| Action | Bounded 6D Cartesian residual twist/increment (position + orientation); optional gripper command if verified safe |
| Nominal command | Cartesian trajectory generated by classical planner/control, identical in RL and no-RL baseline |
| Low-level control | Impedance/force-aware controller with finite output limits, saturation and fail-safe |
| Update | Policy at slower frequency than physics; measure action-hold effects rather than assume rates |
| Episode start | Valid grasp and stabilized cube for first curriculum, then progressively learned acquisition |
| Termination | Verified turn completion; invalid cube state; slip; excess force; collision; object loss; timeout; numerical instability |
| Reward | Incremental **measured** target-layer progress, completion after independent physical verifier, contact stability; penalties for non-target turns, slip, force exceedance, collision, failure, energy/time cost |
| Algorithm | SAC initial candidate, PPO matched-budget comparison; hyperparameters selected empirically |

Specify all units, coordinate frames, action clipping, normalization bounds, episode and control frequencies before training. Use angle wrap conventions and distinguish target-layer rotation from cube-body motion. Avoid granting the policy the goal puzzle state as a hidden simulator toggle.

## 4. Residual controller implementation contract

At each control interval, nominal Cartesian command `u_nom` comes from a conventional trajectory. A residual policy outputs `delta_u`, clipped within documented translational and angular bounds. An independent constrained low-level controller maps `u_nom + delta_u` into actuator targets/torques while preserving joint limits, gripper-force limits and impedance stability. Contact events use sensor estimates; simulator truth used for offline audits, not policy shortcuts.

Do not let RL select arbitrary high-frequency torque or disable limits. If learned stiffness/force setpoints are later tested, treat as a **separate, bounded ablation** with reviewed safety conditions.

## 5. Curriculum (gated, not assumed to work)

1. Stable, known grasp; single axis; fixed cube pose and friction.
2. Randomized target-face axis and modest pose misalignment.
3. Friction/grip-force variation and starting-angle perturbation.
4. Task-relevant disturbances, limited perceptual noise, changed cube orientations.
5. Regrasp/handoff and later role-switch skills, only after reliable foundational behavior.

No full scramble learning or multi-agent RL at initial training.

## 6. Reward safety and anti-hacking tests

- If command is issued but face doesn't physically turn: **no completion reward**.
- If intended layer turns while adjacent layer turns illegally: episode failure.
- If a cubie teleports or constraints snap it into place: episode failure.
- If an opponent arm does the turn while the policy does nothing: score motion correctly, do not assign spurious learning credit.
- If solver or simulator state is manually set to solved: no success.
- If policy learns to collide or exploit unrealistic friction, mark invalid and fix physics, not celebrate reward.
- Assert all reward terms have measured observables, sensible scales and documented tests.

## 7. Baselines and ablations

**B0:** Classical Cartesian/impedance trajectory, same gripper, cube and task.  
**B1:** Classical + randomized bounded residual (negative control).  
**B2:** Classical + SAC residual policy.  
**B3:** Classical + PPO residual policy if resource budget permits.  
**B4 (optional):** RL policy without nominal baseline, only if meaningful and computationally feasible.

Controlled ablations: contact-force feedback off, reward terms off, posture observation removed, curriculum stage, tool geometry candidate, optional stiffness learning. Never compare methods trained/evaluated on different scramble distributions while claiming causal advantage.

## 8. Evaluation splits and metrics

Fix reproducible train/validation/held-out seeds before final tuning. Randomize legal face/cube poses, physically plausible friction, starting grasp offset and disturbances. Reserve a separate test subset and do not retune to it.

Track: verified completed turns / attempts; unintended layer turns; robot/cube collisions; slip rate; high-force events; completion angle error; controller saturation; peak contact wrench; recovery count; simulation steps/sec; training wall clock; environment interactions and confidence intervals. Later evaluate 180° turns and unseen scramble/hand-off sequences.

Report multiple policy training seeds where affordable; if only one is possible, explicitly limit any stability claim. Pre-register pilot sample size and tolerances in `VALIDATION_PLAN.md` *after calibration*.

## 9. Training resource budget

Initial CPU-only benchmark must measure: no-arm cube physics, two-arm idle, classical turning, policy inference overhead, training throughput, memory, thread/core utilization and rendering off/on. Use a small policy, compact state, headless rollout, limited parallel environments based on measured contention and a fixed per-phase compute cap decided from observed performance.

Never promise a fixed training duration before throughput evidence. Checkpoints and metrics must contain seeds, hyperparameters, dataset split and source/model commit identifiers.

## 10. Phase 3 exit gate

- Reproducible trained policy with documented config/weights and authorized license.
- Verified physical success classification, no prohibited cube-state updates or physics shortcuts.
- Matched held-out comparison to classical B0, with any negative result plainly reported.
- Failure examples, CPU cost, trajectories and plots included.
- User approval recorded before expanding into multi-skill learning.
